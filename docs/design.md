# 设计与数据流程

## 存储和身份

fact 位于 `facts.md` 的二级标题段，SOP 位于 `sops/*.md`。显示标题与条目定位分开，所有工具交换 `{namespace, kind, key}`。同名不同类型、带标点的标题和不同空间都有独立身份。

全局空间为 `default`。项目空间使用宿主归一化工作区或规范化路径的持久映射，分支共享项目知识。旧的 basename 空间通过显式迁移关联，迁移保留来源。

## 上下文

L1 在磁盘上保存全量活跃目录。动态上下文将项目和 global 分配独立字符预算，折叠条目和手写规则时保留完整内容的读取入口。

宿主 `systemPrompt.variable` 提供文本，context 只引用固定变量，正文不会被再次当模板解析。宿主比较内容快照，相同内容不重复追加。L0 和 runtime skill 使用同一份核心规则模板。

## 修改与恢复

同一命名空间的正文、meta、索引和历史修改使用同一个写入口和互斥协议。锁只在文件提交期间持有，不跨模型思考。跨空间操作按稳定顺序获得锁。

历史明确记录条目身份、快照 id、正文、元数据和生成时间。更新、归档、恢复前保存当前版本，历史失败直接中止修改。恢复按快照 id 进行，避免前缀或文件名字典序推断。

读取错误直接报告，元数据存在但不可解析时不会被当空库写回。只读工具不执行初始化或迁移。管理入口可修复遗留元数据和归档状态，并记录迁移结果。

## 来源

新证据关联真实调用 id、session 和 seq，旧式 `code-dispatch`、新式 `ptc-dispatch` 和普通 `tool/result` 均可追溯。工具调用的失败状态根据宿主 `message.isError` 与进程退出码判定，失败调用不进入有效证据。证据版本与正文版本一起保存。纯措辞更新可以沿用原来源，提供新验证证据则更新整个来源组。

`memory_expand` 使用宿主 `sessionQuery` 的事件窗口和文本提取接口。记录的是验证事件，不能把一个会话里所有工具结果都等同于当前条目的证据。`memory_review` 从当前会话的成功验证调用提取脱敏证据片段，登记待复核的新旧事实冲突。

## 检索与维护

一次扫描解析 facts 并收集 SOP 文档。BM25 处理检索，成对内容比较一次计算后分别产生一致、近重复及合并候选。相似度本身不决定归档。

程序维护仅自动合并同名同内容段，其他问题归入 `actionable` 清单。fact 冲突、跨条目重复和待确认候选共享同一状态判断，冷条目仅提供复核线索。

任务收尾核对与存量自动维护共用空间级派发入口和冷却记录。收尾核对按父会话与命名空间积累成功工具证据的指纹并去重，剔除已绑定来源写入记忆的调用；达到证据数量、至少三个有效用户回合且共享冷却到期后，将有界摘要及精确父来源交给固定核对会话。有界窗口保留最近三个有效回合的代表证据。派发冷却与证据消费分离，完整结束后消费该批证据，失败、超时或延期时保留待处理证据。

`notify` 模式将可行动事项保存在状态台账中供工具查询；`auto` 模式先运行程序扫描，对可行动事项或索引超限交给固定整理会话，按审阅台账分批推进，并在日常实质变更累计达标后安排下一轮。整理模型显式配置，核对模型每次从父会话解析。模型工作与文件提交分离。修改已有条目前必须完整读取同一版本（包含类型、空间、条目 key 和 revision，读取尾页不算完整读取），新建条目可直接创建，结案版本由实际读写记录推导。

`maintenance-workers` 使用公开存储域按父会话保存两个槽位，身份不随 namespace、cwd 或 memoryDir 改变。首次通过公开 `agents.create` 建立独立上下文，以后 `agents.resume` 恢复原 ID；setup 为本次运行安装模型选择、请求输出上限和工具作用域。完成工具调用公开 `concludeTurn`，执行器等待成功权威回执、正常 turn end、idle 和持久化后结案。PTC 的内部完成还需等待外层调用成功。每次释放 Agent handle，保留会话与审阅进度，读取资格、预算和 usage 按本次 run 单独计算。需要正文的证据通过公开 sessionQuery 按白名单事件补读；历史压缩保留 session ID。

## 工具与状态组件

`common` 提供日常检索、读写和冲突登记，`manage` 补充历史、归档、候选和迁移。每层都有 `read` / `write` 访问级别，子代理默认 `read`。自动维护使用专用激活入口和明确调用、写入、时间预算。

核心插件通过 `layeredMemoryActivity` 服务发布当前运行阶段与维护结果，通过父会话限定的 worker facade 提供固定槽位、分页历史和停止操作。独立的状态子包通过 `typert` 读取这些能力，在 `conversation.composer.dock` 单行展示进度、真实变更数及未完成原因。点击展开插件浮层，主对话位置保持稳定；历史只投影维护回复、工具和实际错误。已有原生 catalog 历史保留，新维护执行不再按次数新增菜单项。
